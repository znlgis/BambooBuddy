# 打包与分发：便携 EXE 与安卓 APK

> 目标：**Windows 上一个 exe 双击就跑，不装**；**安卓一个 apk 装上就玩**。
> 同一份站点产物（`apps/site/dist`）喂给两个壳，游戏代码零改动。

---

## 0. 一条命令

```bash
pnpm dist:win    # → apps/desktop/src-tauri/target/release/bamboo-buddy.exe
pnpm dist:apk    # → apps/mobile/android/app/build/outputs/apk/release/app-release.apk
```

两个脚本都会先构建站点产物，再交给各自的壳。
仓库里也提交了生成好的图标与安卓工程，所以不需要先跑一次 `pnpm icons` 才能打包（只有换图标时才需要）。

---

## 1. 目录结构

```text
apps/site/                     Vue 应用（唯一的产品代码）
apps/desktop/                  Tauri 2 桌面壳
  src-tauri/tauri.conf.json    窗口尺寸、图标、frontendDist 指向 site/dist
  src-tauri/src/main.rs        20 行的壳
apps/mobile/                   Capacitor 8 安卓壳
  capacitor.config.ts          webDir 指向 site/dist
  android/                     安卓工程（入库，便于复现）
  resources/                   图标与启动图源文件
scripts/make-icons.py          用 Pillow 几何绘制生成图标
scripts/build-apk.mjs          自动挑 JDK 17–21 后调 gradlew
scripts/make-keystore.mjs      生成安卓签名密钥并打印 Secrets
scripts/check-packaging.mjs    打包配置体检（接进 pnpm verify）
```

---

## 2. 为什么是这个组合

| | 选型 | 理由 |
|---|---|---|
| Windows | **Tauri 2** | 用系统自带的 WebView2，产物只有几 MB；Electron 同样功能要 150 MB |
| 安卓 | **Capacitor 8** | Web 套壳的行业标准；内置本地服务（`https://localhost`），ES module / IndexedDB / WebGL 全部按浏览器标准工作 |
| 语音 | **原生 TTS** | **Android WebView 没有实现 Web Speech API**，只靠 `speechSynthesis` 安卓版会全程没旁白 |

> Electron 还有个坑：`index.html` 用 `<script type="module" crossorigin>`，
> 在 `file://` 下会被 Chromium 的 CORS 拒绝，必须额外注册自定义协议。
> Tauri 默认就走自定义协议，这个坑不存在。

## 3. 平台适配层（架构早就留好了）

`packages/platform/src/runtime.ts` 做运行环境探测，**不 import 任何壳的 SDK**：

```ts
detectRuntime(): 'web' | 'tauri' | 'capacitor'
nativeTextToSpeech()   // 通过 window.Capacitor.Plugins 取原生 TTS
nativeApp()            // 安卓返回键 / 退出
```

好处：Web 包体积零增长，浏览器里也不会有插件报错。

### 语音怎么选

```ts
speak(text, locale) {
  ① 原生 TTS（安卓）→ 安卓系统语音引擎
  ② Web Speech API（桌面 WebView2 / 浏览器）
  ③ 都没有 → 静默降级，只保留音效，绝不报错卡住
}
```

### 安卓返回键

在游戏 / 任务 / 装扮 / 日记 / 家长页按返回 → 回到小屋；已经在小屋 → 才退出应用。
不处理的话，孩子在游戏里误按返回键会直接把应用关掉。逻辑在
`apps/site/src/shell/backButton.ts`，有单测覆盖。

### 竖屏与全屏

- `AndroidManifest.xml`：`android:screenOrientation="portrait"`
- `styles.xml`：沉浸全屏 + `windowLayoutInDisplayCutoutMode=shortEdges`（刘海屏）
- CSS：`#app` 用 `env(safe-area-inset-*)` 让开刘海与手势条

## 4. 签名与安全

| 文件 | 是否入库 | 说明 |
|---|---|---|
| `apps/mobile/android/keystore.properties` | ❌ | 本地签名配置 |
| `*.keystore` | ❌ | **务必自己备份**；丢了就只能让用户先卸载再装新版 |
| `apps/mobile/android/local.properties` | ❌ | 本机 SDK 路径 |

没有 keystore 时，Gradle 会**自动退回 debug 签名** —— 产物依然可以安装，方便自己构建。
CI 检测到没有签名 Secrets 时也会用 debug 密钥签，Release 说明里会写明。

### 想要「以后能直接覆盖安装、存档不丢」：跑一次 pnpm keystore

```bash
pnpm keystore     # 生成 apps/mobile/android/bamboo-release.keystore + keystore.properties
```

它会打印四样东西（keystore 的 base64、storePassword、keyAlias、keyPassword），
贴进 **Settings → Secrets and variables → Actions** 的四个同名 Secret 即可：

| Secret | 内容 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | keystore 文件的 base64 |
| `ANDROID_KEYSTORE_PASSWORD` | storePassword |
| `ANDROID_KEY_ALIAS` | keyAlias |
| `ANDROID_KEY_PASSWORD` | keyPassword |

### 首次构建需要

1. **JDK 17–21**（JDK 25 超出 Gradle 8.14 的支持范围；`build-apk.mjs` 会自动找）
2. **Android SDK**：`platforms;android-36` + `build-tools;36.0.0`（Capacitor 8 要求 compileSdk 36）
3. **Rust 工具链** + **MSVC C++ 生成工具**（Tauri）
4. **WebView2 运行时**（Win10/11 通常已内置）

## 5. 分发

- **Windows**：直接发 `bamboo-buddy.exe`，双击即用，不需要安装、不写注册表。
  未签名的 exe 首次运行会有 SmartScreen 提示（"更多信息 → 仍要运行"）。
- **安卓**：直接发 apk，用户需要在设置里允许"安装未知来源的应用"。

**建议**：先直接分发文件，跑通体验再考虑上架。

## 6. 用 GitHub Actions 自动发布

推一个 tag 就会自动构建两个平台并挂到 GitHub Release：

```bash
git tag v0.2.0
git push origin v0.2.0
```

流程（`.github/workflows/release.yml`）：

```text
version  解析 tag → 版本号与 versionCode
web      构建站点产物 + 类型 / lint / 单测 / 内容校验 / 打包配置体检 / 体积守卫
e2e      开发服务器 e2e + 生产产物 e2e（与两个平台并行）
windows  Tauri 构建便携 exe（windows-latest；收集时体积门禁 > 10MB 失败）
android  Capacitor 构建 apk（ubuntu-latest，JDK 21 + android-36；签名校验 + 体积门禁）
release  两个产物挂到 GitHub Release（needs 含 e2e：玩法门禁没过就不发）
```

**站点产物只构建一次**，两个平台下载同一份，保证 exe 与 apk 里的网页代码完全一致。

**版本号自动注入**：tag `v1.2.3` → 安卓 versionName 1.2.3 / versionCode 10203，
Tauri 的 `tauri.conf.json` 也会被改成同一个版本。带 `-` 的 tag（如 `v1.0.0-beta.1`）自动标为预发布。

### 手动试跑

在 Actions 页面选 **Release** → **Run workflow** 可以只出产物、不发 Release（`github.ref_type` 不是 tag）。
勾选 **require_signed_apk** 则在没有配 Secrets 时直接失败（默认不勾：没有 Secrets 就用 debug 签名打一个能装的包）。

### 本地体检

不装 Rust/JDK/SDK 也能检查配置是否完整：

```bash
pnpm pack:check
```

它会检查 tauri.conf / Cargo.toml / capacitor.config / AndroidManifest / build.gradle /
中英应用名 / release.yml / 图标文件是否齐全。`pnpm verify` 已经包含这一步。

---

## 7. 打包没有改变的东西

- 游戏代码一行没改：两个壳都只是加载同一份 `apps/site/dist`
- 存档仍然是 IndexedDB，在桌面与安卓上都能持久保存
- 中英切换、`?lang=`、`?autoplay=1` 在两端都照常工作
- `pnpm verify` 与端到端测试完全不受影响（它们针对的是 Web 产物）
