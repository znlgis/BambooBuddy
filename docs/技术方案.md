# 《熊猫宝宝的一天》技术方案

> 状态：**已落地（v1）** ｜ 日期：2026-10-19
> 技术选型参考 `D:\self\code\CHAGS` 的技术方案。本文档只定技术路线、架构与关键取舍，产品方案见附件《熊猫宝宝的一天》儿童日常生活养成游戏方案。
> 一句话结论：**用 Phaser 4 + Vue 3.5 的 H5 方案，按「外壳 + 引擎工具 + 玩法模板 + 内容数据 + 独立玩法包」五层来做；8 个玩法模板撑起 10 个日常主题，内容与代码分离，逻辑与渲染分离，一条 `pnpm verify` 定义"完成"。**

---

## 0. 结论速览

| 决策项 | 选型 | 一句话理由 |
|---|---|---|
| 游戏引擎 | **Phaser 4.2.1**（裁剪版 vendor，MIT） | 纯代码、可 diff、可单测；只在 `games/*` 与 `phaser-kit` 出现 |
| 应用外壳 | **Vue 3.5 SFC + Pinia + Tailwind 4** | 小屋 / 任务 / 装扮 / 日记是 UI 密集型，SFC 改一个页面只动一个文件 |
| 语言 | **TypeScript 5.9.3 strict** | 与 vue-tsc 兼容（TS 7 会崩，见 CHAGS 2.3 的实测） |
| 构建 | **Vite 8 + pnpm workspace** | 多入口 + 代码分割，每个玩法自动独立 chunk |
| 内容 | **JSON + zod，构建期校验；中英各一份补丁** | 换任务 = 换内容；`content:check` 在 CI 拦错，英文漏翻也拦 |
| 双语 | **语言是外壳与内容的事，游戏不知道语言存在** | `?lang=` / 头部按钮切换；英文文案与英文关卡脚本都是懒加载 chunk |
| 玩法 | **8 个玩法模板 + 10 条任务内容** | 让第 11 个主题的边际成本接近零 |
| 存储 | **IndexedDB（本地优先）+ 可替换接口** | 无后端、无账号，儿童合规最安全 |
| 音频 | **WebAudio 合成 + SpeechSynthesis** | 零音频文件先把"听"通道跑通 |
| 测试 | **Vitest + vue-tsc + Playwright + 内容校验 + 体积门禁** | `pnpm verify` 全绿才算完成 |
| 后端 | **MVP 完全不做** | 纯静态站点；家长报告只读本机存档 |

**三条架构铁律**（与 CHAGS 一致）：

1. **逻辑与渲染分离**：规则写在 `*.logic.ts` 与 `packages/progress`，不 import Phaser，可脱离浏览器单测。
2. **游戏不得自己碰环境**：存档、音频、生命周期一律通过注入的 `PlatformServices`；游戏里没有 `localStorage` / `fetch` / `wx.*`。
3. **每个玩法必须能被无头直达**：`#/play/<id>?autoplay=1`，另有 `?instant=1` 跳过过场。否则自动化测试与 AI 协作都做不了。

## 1. 从产品定位反推技术约束

定位：**面向 4–8 岁儿童的轻量日常养成游戏，核心不是数值内卷，而是"孩子照顾熊猫 → 熊猫开心成长 → 孩子愿意模仿日常好习惯"。**

| # | 产品诉求 | 技术约束 |
|---|---|---|
| 1 | 家长随手把手机给孩子，不能要求装 App | H5 / PWA-ready，扫码即玩；纯静态 |
| 2 | 4–8 岁注意力短，单局 30–90 秒 | 单局短、随时中断可恢复、无长连接 |
| 3 | 场景常在弱网 / 车内 / 老家 | 零外部资源（几何绘制 + 合成音效）；全量静态资源体积极小 |
| 4 | 家里旧安卓机、旧 iPad 也要能跑 | 2D、低端机 30fps 以上、无重型后处理 |
| 5 | **核心指标是习惯模仿** | 无失败惩罚、无倒计时、语音优先、大按钮、少文字 |
| 6 | 合集要能长到更多主题 | 模板库 + 内容 JSON + 契约化，新增主题 = 加内容 |
| 7 | 家长会问隐私 | 无广告 SDK、无社交、不采集儿童信息、数据默认只存本机 |
| 8 | 很可能由 AI 辅助开发 | 全文本资产（可 diff）、可单测、一条命令验证、确定性随机 |

> 第 8 条直接否掉了"编辑器里拖拽出场景"的方案：场景文件无法 review、无法 diff、无法被自动化验证。CHAGS 用 Phaser 而不是 Cocos 的核心理由，在本项目同样成立。

## 2. 技术选型细节

### 2.1 引擎：Phaser 4.2.1（裁剪版）

- 完整版 `phaser@4.2.1` 打出来约 347 KB gzip；本项目与 CHAGS 一样只用 Scene / GameObjects(Container/Graphics/Text/Zone) / Input / Tweens / Time / Cameras / Scale。
- 采用 CHAGS 的裁剪产物 `packages/phaser-kit/vendor/phaser-trim.esm.js`（约 221 KB gzip），通过 Vite alias 替换裸 `phaser` 导入；类型仍解析到 phaser 包，typecheck 不受影响。
- **引擎绝不打进首屏**：只有进入玩法时才加载，且加载一次后浏览器长期缓存。`scripts/check-size.mjs` 守卫这条。

### 2.2 外壳：Vue 3.5 + Pinia + Tailwind 4

小屋、任务、装扮、日记都是 UI 密集型页面；SFC 单文件组件让"改一个页面只动一个文件"。Phaser 被隔离在 `games/*` 与 `packages/phaser-kit`，外壳主包 import 不到它。

**Vue × Phaser 集成踩坑清单**（与 CHAGS 相同，写进 code review）：

1. Phaser 实例必须用 `shallowRef` 或 `markRaw` 持有；`ref` 会深度代理整个 Phaser 对象图。
2. 游戏容器不要放进 `<KeepAlive>`/`<Transition>`；离开路由前必须 `await unmount()`（`game.destroy(true)`）。
3. 给游戏模块加 HMR 边界：编辑 Phaser 场景时整页刷新，否则热替换会叠出多个 canvas。
4. 不要在 `computed`/`watch` 里持有 Phaser 的 GameObject。
5. 宿主组件最小实现：`defineProps` + `shallowRef` + `onMounted`/`onBeforeUnmount`（见 `PlayView.vue`）。

|---|---|

### 2.4 美术与音频：阶段 0 策略

- **零位图、零音频文件**：所有角色 / 房间 / 食物 / 衣服 / 玩具用 Phaser Graphics 与 SVG 几何绘制；音效用 WebAudio 振荡器合成；旁白用浏览器 TTS。
- 好处：首屏与非代码资源为 0 KB、无版权风险、可 diff；代价是观感朴素。
- 换成真资源时**代码不用改**：角色绘制集中在 `phaser-kit/panda.ts` 与外壳的 `PandaBuddy.vue`；音频只改 `platform/web.ts` 的 `AudioBus` 实现。

### 2.5 数据与存储

- MVP 无后端。存档在 IndexedDB（`bamboobuddy/kv/save`），不可用时自动降级内存（隐私模式）。
- 存档带 `schemaVersion` 与 `migrate()`：现在写迁移函数几乎零成本，等有用户数据再补就是灾难。坏字段逐条兜底，未来版本才整体清空。
- 只保留最近 30 天的日记录，避免存档无限增长。

### 2.6 测试与质量保障

| 层级 | 工具 | 覆盖内容 |
|---|---|---|
| 类型 | `vue-tsc --noEmit` | 全仓 strict，含 .vue |
| Lint | eslint 10 flat + vue + typescript-eslint | 风格；禁止纯逻辑层 `Math.random` / `Date.now`；禁止外壳 import `@bamboo/content/full` |
| 逻辑单测 | Vitest | `packages/progress` 与 8 个 `*.logic.ts`：判定、奖励、衰减、迁移、关卡语义 |
| 内容校验 | 自研 `content:check` | zod schema + 模板关卡 schema + 时段覆盖 + 语义约束（均衡目标/箱子匹配/答案存在）+ 伤害性文案检查 |
| 端到端 | Playwright | 10 个玩法 autoplay 全通关、真实指针操作（刷牙/整理/睡觉）、刷新后进度、家长锁与清档、生产产物懒加载 |
| 体积 | `scripts/check-size.mjs` | 首屏 / 单个懒加载 chunk / dist / 非代码资源共七项预算 |

一条命令：`pnpm verify` = typecheck → lint → test → content:check → build → size。对 AI 协作来说，这条命令就是"完成"的定义。

### 2.7 明确"暂不做"

账号 / 后端 API / 排行榜 / 多人 / 内购 / 广告 / 抽卡 / 3D / CMS / 第二语言 / 到期复习 / PWA（后续可加）。理由：都会显著抬高成本与合规风险，且对"孩子今天愿意模仿一个好习惯"几乎无贡献。

## 3. 架构

### 3.1 分层

```text
┌──────────────────────────────────────────────────────────────┐
│  外壳 apps/site（Vue 3.5 SFC）                               │
│  小屋 · 任务 · 装扮 · 日记 · 家长页 · 游戏宿主               │
│  状态 Pinia · 路由 hash composable · 样式 Tailwind           │
└──────────────┬───────────────────────────────────────────────┘
               │ 动态 import（代码分割，Phaser 只在这里出现）
               ▼
┌──────────────────────────────────────────────────────────────┐
│  玩法 packages/templates/<template>.ts（Phaser Scene）       │
│  判定 packages/templates/<template>.logic.ts（纯 TS，可单测） │
│  入口 games/daily/src/games/<task>.ts（defineGame）           │
└──────────────┬───────────────────────────────────────────────┘
               │ 只依赖下面这些，绝不反向依赖外壳
               ▼
┌──────────────┬──────────────┬──────────────┬────────────────┐
│ game-kit     │ content      │ phaser-kit   │ i18n           │
│ 契约/事件     │ 任务数据+校验 │ 引擎启动/美术 │ 中文文案表      │
└──────────────┴──────┬───────┴──────────────┴────────────────┘
                      │
             ┌────────┴─────────┐
             │ progress │ platform │  存档/推荐/奖励 · 存储/音频/生命周期
             └───────────────────┘
```

`game-kit` 与 `content` **不含 Phaser 依赖**，外壳可以安全 import。

### 3.2 核心契约

`packages/game-kit/src/contract.ts`：

```ts
export interface GameManifest {
  id: TaskId; title: string; version: string; template: TemplateId;
  designSize: { width: number; height: number }; ageRange: [number, number];
}

export interface GameEventMap {
  'session:start': { at: number };
  'scene:enter': { scene: string };
  'task:retry': { taskId: TaskId; step: string };
  'task:complete': { taskId: TaskId; stars: Stars; mistakes: number; correct: number; total: number; durationMs: number };
  'session:exit': { reason: 'complete' | 'quit' | 'replay'; progress: number };
}

export interface GameContext {
  container: HTMLElement;
  manifest: GameManifest;
  task: TaskDetail;                 // 外壳已经加载好的完整内容
  services: PlatformServices;       // storage / audio / lifecycle / telemetry
  locale: 'zh-CN';
  reducedMotion: boolean;
  debug?: { autoplay?: boolean; instant?: boolean };
  completedBefore: boolean;
  emit<K extends keyof GameEventMap>(type: K, payload: GameEventMap[K]): void;
  requestExit(reason?: 'quit' | 'replay'): void;
}

export interface GameModule {
  manifest: GameManifest;
  mount(ctx: GameContext): Promise<void>;
  unmount(): Promise<void>;
  pause(): void;
  resume(): void;
}
```

- 一条 `task:complete` 是**唯一**的完成信号：外壳据此写存档、发奖励、显示 toast；模板不允许自己拼奖励。
- `session:exit` 的 `replay` 让「再玩一次」原地重开，不用回任务页再找。
- `PlatformServices` 是唯一平台出口：游戏里出现 `localStorage` 即视为 bug。

### 3.3 八个玩法模板

| 模板 | 交互原语 | 判定（纯函数） | 用于 |
|---|---|---|---|
| `scrub` | 按住工具来回刷；刷干净后冲水/擦干 | 最近点位 + 半径、每点 `rubs` 次、`finishTaps` | 刷牙 / 洗手 / 洗澡 |
| `feed` | 食物拖到嘴边，一口一口吃完 | 每口递减、总口数、类别均衡 | 吃饭 |
| `dress` | 衣物拖到正确部位 | 槽位匹配、全部穿上 | 穿衣 |
| `order` | 按顺序点睡前道具 | 当前步骤 id、错点不清进度 | 睡觉 |
| `tidy` | 玩具拖进对应箱子 | 类别匹配、全部归位 | 整理 |
| `rhythm` | 竹竿开合，窗口内点按 | 墙钟三角波、`zone`、220ms 连点门、连击音高 | 运动 |
| `pick` | 认情绪 + 安慰 | 目标情绪、轮次推进、安慰动作 | 情绪 |
| `learn` | 颜色 / 形状 / 数字点选 | 答案下标、可无限重试 | 学习 |

设计约束：

1. **每个模板必须能被自动走完**，且走的是与真实操作同一条处理函数（不是另写"自动通关"分支）。
2. **零失败**：刷不干净可以继续刷；点错只是提示，不清进度、不结束、不给 0 星。
3. **模板 id 的唯一事实来源**是 `packages/content/src/ids.ts` 的 `TEMPLATE_IDS`；`templates/schemas.ts` 用 `Record<TemplateId, ZodType>` 约束 —— 少登记一个在 typecheck 就报。
4. 关卡脚本的 0–1 坐标由模板映射到设计坐标；需要 e2e 真实点的三个模板把最终坐标放在 `templates/layout.ts`（纯常量，不 import Phaser）。

### 3.4 内容模型

每条任务拆成两半（与 CHAGS 的 `content` / `content-full` 同一条教训）：

| 层 | 文件 | 内容 | 谁用 |
|---|---|---|---|
| 摘要 | `content/src/tasks/<id>.json` | id / 标题 / emoji / 颜色 / 时段 / 模板 / 时长 / 收益 / 奖励 / 习惯 / 日记一行 / 提示 | 小屋、任务、装扮、日记（首屏） |
| 详情 | `content/src/details/<id>.game.json` | 语音文案（intro/done/retry）+ 关卡脚本 | 玩法、内容体检（动态 import） |

`loadTask()` 是外壳拿到完整内容的唯一入口；eslint 禁止外壳直接 import `@bamboo/content/full`。

内容体检除 zod 外还做语义检查：

- 每个任务模板都有 schema，且脚本能过；
- 早/中/晚每个时段至少 2 个任务；
- 8 个模板全部被真实内容用到；
- 吃饭的均衡目标必须有对应食物；整理每个玩具类别必须有箱子；情绪每轮选项必须包含答案且不重复；穿衣槽位不重复；睡前步骤 id 不重复；
- 文案里不允许出现"失败 / 惩罚 / 笨蛋 / 输了 / 淘汰"。

### 3.5 存档结构

```ts
interface SaveData {
  schemaVersion: 1;
  updatedAt: number;
  pet: {
    name: '竹竹'; xp: number;
    stats: { fullness; energy; clean; mood; health };   // 0–100，下限 10
    lastDecayDay: 'YYYY-MM-DD';
    shoots: number; fragments: number; unlocked: string[];
    stickers: TaskId[]; intimacy: number;
    careDays: Partial<Record<'pat'|'hug'|'highfive', string>>;
    equipped: Partial<Record<'hat'|'bib'|'outfit'|'backpack'|'shoes', string>>;
    room: Partial<Record<'wallpaper'|'bed'|'shelf'|'toyCorner'|'rug', string>>;
    feeds: number;
  };
  tasks: Record<TaskId, { stars; completions; lastPlayedAt; lastCompletedDay; streak; bestStreak }>;
  days: Record<'YYYY-MM-DD', { completed; rewards; stickers; care; seconds; restDismissed }>; // 最近 30 天
}
```

**数值口径**：

- 状态只增不减（任务收益）＋每天一次轻衰减（饱腹/清洁 −10、精力 −9、心情 −7、健康 −4）；下限 10，永不归零。
- 星星：失误 ≤1 → 3 颗，≤3 → 2 颗，其余 1 颗；没有 0 颗。
- 当天第一次完成给全份奖励；同一天重复玩给一半（最低 1 根竹笋、3 成长值）。
- 每完成第 3 个不同任务得 1 枚装扮碎片。
- 连续 3 天完成同一任务得贴纸（每个任务一张）；断签只重新计数。
- 成长阶段：0 / 60 / 160 / 300 成长值；一次任务约 10–14。
- 亲密度：摸头 +1、抱抱 +2、击掌 +2；5 / 12 / 22 / 35 解锁小动作。

### 3.6 儿童向交互规范（code review 清单）

- 可点区域 ≥88×88 逻辑像素；按钮不做悬停依赖。
- 命中区必须覆盖整颗按钮：Phaser 的 Container 命中测试会再加一次 `displayOrigin`，
  `setInteractive` 的矩形要按左上角原点给 `(0, 0, w, h)`（见 `phaser-kit/src/hitArea.ts`）；
  传居中矩形会让可点区只剩左上 1/4，表现为"点中间时好时坏"。
- 无失败惩罚、无倒计时、无限重试；错了只说"再试一次"。
- 语音引导不阻塞操作（与 CHAGS 的"听完故事"相反：日常模仿需要即时反馈）；关键文案同时上屏。
- 不靠颜色单独传达信息；对/错同时有图标与音效。
- 声音总开关三处同一状态；静音立即停语音。
- 尊重 `prefers-reduced-motion`；20 分钟休息提醒一天一次。
- 家长锁：长按标题 3 秒进家长页；清档长按 3 秒。
- 无广告、无内购、无社交、不采集儿童个人信息。

### 3.7 中英文双语

语言只影响三层：**界面文案、内容文案、语音**；游戏代码与存档完全不知道语言的存在。

| 层 | 事实来源 | 加载方式 |
|---|---|---|
| 语言清单 | `packages/content/src/ids.ts` 的 `LOCALES / Locale / DEFAULT_LOCALE` | game-kit 与 i18n 都从这里再导出，避免三处各写一份 |
| 界面文案 | `packages/i18n/src/messages.ts`（中文）+ `en.ts`（英文） | 中文常驻；英文表是独立 chunk，`ensureMessages('en')` 动态加载 |
| 内容摘要 | `packages/content/src/tasks/<id>.json` + `i18n/en/<id>.json` 补丁 | 英文补丁集中在 `i18n/en/summaries.ts` 一个小 chunk，切语言时下载 |
| 内容详情 | `details/<id>.game.json` + `i18n/en/<id>.game.json` | 每条英文详情单独懒加载，只有进入那个玩法才下载 |
| 语音 | `AudioBus.speak(text, locale)` → `speechLang(locale)` | zh-CN / en-US 各自挑嗓音、语速略不同 |

几条实现纪律：

1. **游戏不知道语言**：外壳把已经翻译好的 `TaskDetail` 交给游戏，场景只读 `ctx.task`；场景里的通用按钮走 `ctx.locale` 建的取词器。
2. **切换前先就位**：`main.ts` 与语言 store 都会先 `await Promise.all([ensureSummaries, ensureMessages])` 再换状态 —— 不会出现"界面英文、内容中文"的半截状态。
3. **英文漏翻是构建期错误**：`content:check` 对每条任务把摘要补丁 + 详情补丁合并后重新过 schema，并检查 `levelScript` 里零中文；界面文案表则由 `Record<MessageKey, string>` 在 typecheck 拦住少键。
4. **`<html lang>` 与 `document.title` 跟着切**；`?lang=en` 可分享，选择记进 `localStorage`（`bamboo.locale`）。
5. **版面要点**：英文更长（"Bamboo Leaf Hat"、"Next: Turn off light"），所以装扮名允许换行、玩法 HUD 用 i18n 模板、食物标签长词自动缩一号、步骤名底下加一张药丸卡。

### 3.9 三款隐藏小游戏（竹林小门）

完成当天四件小事后，小屋出现「竹林小门」，门后是三款按 4–8 岁重做的街机小游戏（消灭星星 / 弹一弹 / 俄罗斯方块），每天每款一次。

- **契约**：`packages/game-kit/src/arcade.ts`（ArcadeManifest / ArcadeContext / ArcadeModule / ArcadeEventMap）—— 不含 TaskId、不含星星、不发 `task:complete`。硬套日常玩法的 `GameContext` 会把「任务」概念漏进彩蛋系统。
- **实现**：`games/arcade`，三款各自 `*.logic.ts`（纯逻辑，可单测）+ `*.scene.ts`（Phaser）+ `src/games/<id>.ts` 入口；公共底座 `arcadeScene.ts` 负责 HUD、大按钮、轮次、结算与 autoplay，规则仍是「逻辑与渲染分离」。
- **解锁**：`packages/progress/src/arcade.ts` 的 `arcadeUnlocked(day)` = 今天完成的不同任务数 ≥ `DAILY_TASK_TARGET`（4）。按数量判定，避免「推荐集随时段变化」导致的反复解锁。
- **存档**：v2 新增 `SaveData.arcade`（最高分 / 总次数）与 `DayRecord.arcade`（今天玩过哪些）；`MIGRATIONS[1]` 只补字段，老档的竹笋/星星一根不少。
- **每天每款一次**：宿主在 `arcade:complete` 时调用 `ProgressManager.playArcade()` 落盘；中途退出不消耗当天的机会。
- **入口**：`#/arcade`（游戏厅）与 `#/arcade/<id>`（全屏）；未解锁 / 今天玩过的深链都会被送回该去的地方。
- **不奖励**：彩蛋不发竹笋、成长值、贴纸，不写 `task:complete`，因此不会污染任务经济与连续天数。
- **隐藏触发「竹林小路」**：小屋连点竹竹 7 次（5 秒内）→ 当天 `DayRecord.arcadeSecret = true`；`arcadeUnlocked` 变成「四件小事 **或** 彩蛋」，`arcadeAvailable` 变成「彩蛋 → 随便玩」。保存 schema 因此升到 v3（只加一个布尔字段）。

## 7. 踩坑记录（本项目实测）

1. **zod 4 的 `z.record(enum, number)` 是穷尽记录**：任务只给部分状态收益时，会报另外三个键 missing。改用 `z.partialRecord`。
2. **Phaser Graphics 的 `fillEllipse` 只接受 4 个参数**：颜色/描边必须先 `fillStyle`/`lineStyle`，或走 `cartoon.ellipse` 助手。写 props 时一次性暴露了这个问题。
3. **e2e 不能 import 场景模块**：Playwright 在 Node 里加载 `templates/<id>.ts` 会连带执行 Phaser 顶层依赖。真实指针坐标必须放在不 import Phaser 的 `templates/layout.ts`。
4. **外壳入口不能引 zod**：内容摘要在外壳只做类型断言，运行时校验交给 `content:check`；否则 zod（约 25 KB gzip）会跟着进首屏。为此把常量拆到 `@bamboo/content/ids`。
5. **Phaser 实例必须 shallowRef**，且 unmount 必须 `game.destroy(true)`，否则路由切换会残留 canvas 与 RAF 循环。
6. **重复按同一天结算**：日记录里的 `completed` 是去重的，重复玩只更新星星/次数，不会重复给"首次完成"奖励 —— 由单测守住。
7. **存档迁移不能"版本不等就清空"**：坏字段逐条兜底，只有来自未来版本才整体清空；老玩家的星星不能因一次升级消失。
8. **弯引号在 CJK 字体里是全身宽**：英文副标题 "A Panda’s Day" 最初渲染成 "A Panda’ s Day"（像多了一个空格）。修法是把拉丁字体排在字体栈最前（`Segoe UI / Helvetica Neue / Arial`），中文字形自动回落到 Noto Sans SC / 雅黑 —— 中英排版同时变好。
9. **英文文案必须与中文分开按需加载**：英文表若静态进主包，首屏会从 58.6 KB 涨到 62 KB+ 顶穿预算；现在英文界面表与英文摘要各是一个小 chunk，中文用户完全不下载。
